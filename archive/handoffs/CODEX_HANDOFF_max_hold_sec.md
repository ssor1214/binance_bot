# `--max-hold-sec` 검증 결과 — 빼는 것을 권합니다

작성 2026-08-20 / 대상: `scripts/scalp_bot_e2.py` 의 TIME_STOP 패치

## 요약

시간손절은 **어떤 값에서도 도움이 되지 않았습니다.** 두 개의 독립 모집단에서
같은 결론이 나왔고, 짧게 자를수록 단조롭게 나빠집니다.

현재 라이브 인자는 `--max-hold-sec 300` 입니다. **0(비활성)으로 되돌리는 것을 권합니다.**

## 왜 이 검증을 했나

TIME_STOP 첫 발동 2건이 모두 손실 확정이었습니다.

```
19:24:41 BTWUSDT  LONG  TIME_STOP  보유12.7분 ROE-2.90% 고점ROE+0.00% 순-0.1068
19:32:02 DOGEUSDT LONG  TIME_STOP  보유 7.0분 ROE-1.03% 고점ROE+0.00% 순-0.1104
```

라이브 표본 2건으로는 판단할 수 없어 1초봉으로 직접 쟀습니다.
`scratchpad/sec30/` 에 85심볼 10일치 1초 데이터가 있어 **"300초 시점의 실제 가격"이
존재합니다.** 분봉으로는 불가능한 검증입니다.

## 검증 방법

- 데이터: 85심볼 × 10일, 1초봉
- e2 규칙 그대로 재현: EMA5/10/15 3분할 진입, EMA25 손절, BB·손익비1:2 익절
- 청산 우선순위도 라이브와 동일: `STOP_EMA25 → BB → RR → TIME_STOP`
- 진입 지연 2초 (라이브 실측 중앙값), 수수료 왕복 0.1002% (e1 실측, 100% 테이커)
- 스크립트: `scratchpad/hold_sweep.py`, `scratchpad/hold_sweep2.py`

두 모집단으로 나눠 쟀습니다.

| | 모집단 | 표본 | 중앙 보유 |
|---|---|---|---|
| 1차 | 필터 없음 | 80,212건 | 17초 |
| 2차 | `--min-risk-pct 0.35` 적용 (**라이브와 동일**) | 11,695건 | 46초 |

1차만 보면 라이브(중앙 보유 2분)와 모집단이 달라 결론을 옮길 수 없어서,
라이브에만 있던 최소 손절폭 필터를 넣고 2차를 다시 돌렸습니다.

## 판단

1. **현행 `--max-hold-sec 300`(무조건)은 두 모집단 모두에서 마이너스입니다.**
   1차 -0.0004%p, 2차 -0.0009%p. 크지 않지만 방향이 일관되고,
   120→180→300→600→900 으로 갈수록 단조롭게 개선되어 무제한에 수렴합니다.
   이 단조성이 노이즈가 아니라는 근거입니다.

2. **"손실 중일 때만" 변형 중 300초만 유일하게 플러스(+0.0015%p)입니다.**
   다만 전체 -0.1988% 대비 0.75% 수준의 차이라 **0과 구분되지 않습니다.**
   같은 계열의 120초·180초가 크게 마이너스인 것을 보면 300초의 플러스는
   우연일 가능성이 높습니다. 이걸 근거로 채택하지 마십시오.

3. **시간이 지났다는 사실 자체에 예측력이 없습니다.** 자르는 순간 확정 손실과
   테이커 수수료만 추가됩니다. 이건 이 프로젝트에서 반복 확인된 패턴입니다
   (연패 스로틀·심볼 선별도 같은 이유로 기각됐습니다).

먼저 잘립니다. 300초가 건드리는 건 전체의 16%이고, 그 16%를 자른 결과가 마이너스입니다.

## 권고

```

```

코드 자체는 남겨두어도 무방합니다. 우선순위(`STOP → BB → RR → TIME`)와
`> 0` 가드가 정확히 구현돼 있어, 기본값 0이면 비활성입니다.

## 함께 보이는 더 큰 문제

이 검증에서 e2 전략 자체가 **거래당 -0.1988%** 로 나왔습니다.
이전 추정치(-0.0296% ~ -0.0669%)보다 훨씬 나쁩니다. 차이의 원인은
**진입 지연 2초와 실제 체결가 반영**입니다. 이전 측정은 신호봉의 EMA 값을
그대로 체결가로 가정했습니다.

이 프로젝트에서 진입 지연은 반복해서 지배적 변수로 확인됐습니다
(e1 실측: 0초 +0.0750%, 5초 -0.0079%, 30초 -0.0997%).

**거래당 기대값이 마이너스인 동안에는 심볼 확장·슬롯 확장을 하지 마십시오.**
손실만 증폭됩니다. 시간손절 같은 청산 쪽 튜닝으로는 이 부호를 못 바꿉니다.
바꾸려면 진입 조건 자체를 봐야 합니다.

# 추가 검증 — 슬롯 기회비용까지 넣어서 다시 쟀습니다

위 스윕은 **거래당** 수익률만 쟀습니다. "슬롯을 20분씩 잡고 있으면 그동안 다른
신호를 못 받는 손해가 있지 않냐"는 지적이 나와, 슬롯 수를 고정하고 시간순
선착순 배분으로 다시 돌렸습니다. 스크립트: `scratchpad/slot_sim.py`

## 방법

- 심볼별 신호를 1초봉으로 청산까지 추적해 `(진입시각, 청산시각, 수익률)` 생성
- 전 심볼을 시간순으로 합쳐 슬롯 N개에 선착순 배분
- **빈 슬롯이 없으면 그 신호는 버린다** (라이브와 동일)
- 같은 심볼 중복 보유 금지, 쿨다운 300초 (라이브 `--cooldown-sec`)
- **거래당이 아니라 총액으로 비교** — 그래야 기회비용이 잡힙니다

## 결과 — 슬롯 3개 (현재 잔고 기준 라이브 설정)

|---|---|---|---|---|---|
| 무제한 | 8,374 | 3,321 | -0.1945% | **-1,628.6%** | 53.8% |
| 300초 | 9,982 | 1,713 | -0.1954% | **-1,951.0%** | 38.0% |

| 슬롯 | 300초의 총액 변화 | 체결 변화 |
|---|---|---|

## 해석 — 메커니즘은 맞았고, 부호가 반대였습니다

지적하신 회전 효과는 **정확히 그대로 관측됐습니다.** 300초로 자르니
슬롯 점유가 53.8% → 38.0% 로 떨어졌고, 놓치던 신호를 1,608건 더 잡았습니다.

문제는 **그렇게 더 잡은 거래가 전부 손실이었다는 것**입니다.
총액이 -1,628 → -1,951 로 322%p 악화됐습니다.

핵심은 슬롯 회전이 아니라 **부호**입니다.

- 거래당 기대값이 **마이너스**인 동안: 슬롯을 점유하고 있는 것이 손실을 막습니다.
  회전을 올리면 손실만 증폭됩니다.
- 거래당 기대값이 **플러스로 바뀌면**: 그때는 지적하신 논리가 그대로 성립합니다.
  시간손절이 회전율을 올려 총액을 늘립니다. **그 시점에 이 검증을 다시 하십시오.**

슬롯이 많아질수록 차이가 줄어드는 것(-322 → -198 → -98%p)은 슬롯 제약 자체가
느슨해져 시간손절이 할 일이 없어지기 때문입니다.

"20분, 60분씩 슬롯을 잡고 있으면 어떡하냐"에 대한 실측입니다.
중앙 보유는 **46초**이고, 꼬리는 얇습니다.

**60분 이상 슬롯을 잡는 건 하루 2~3건입니다.** 그리고 이 꼬리의 비용은

# 정정 — 절대 수치는 재검증했습니다 (시간손절 결론은 유지)

## 무엇이 잘못됐나

위 스윕/시뮬레이션 스크립트에 **진입 가드가 빠져 있었습니다.**

라이브 e2 는 진입 직전에 두 가지를 확인하고 스킵합니다.
- `근접손절` — 진입가가 이미 EMA25(손절선)를 넘어섰으면 진입하지 않음
- `익절선통과` — 진입가가 이미 볼린저 목표를 지났으면 진입하지 않음

백테스트에는 이 가드가 없었습니다. 그래서 **손절선 너머에서 진입 → 첫 1초에
손절선 체결 → 그 가격이 진입가보다 유리 → 모델이 '이익'으로 기록**하는 경로가
열려 있었습니다. 실거래에서는 존재할 수 없는 거래입니다.

실측하니 **표본의 39.8%** 가 여기 해당했고, 거래당 **+0.2385%p** 를 허수로
부풀리고 있었습니다.

## 정정된 수치

| | 이전(가드 없음) | **정정(가드 적용)** |
|---|---|---|
| 거래당 | -0.1988% | **-0.1107%** |
| 승률 | 30.1% | **45.1%** |
| 손절 비중 | 76.8% | **49.8%** |
| 중앙 보유 | 46초 | **122초** |

정정 후 청산 분포 (10,129건):

| 사유 | 비중 | 평균 |
|---|---|---|
| STOP_EMA25 | 49.8% | -0.8618% |
| BB | 42.2% | +0.5253% |
| RR | 7.7% | +1.2279% |
| TIMEOUT | 0.3% | +0.5816% |

신호 76,206건 중 **실제 진입은 10,129건(13.3%)** 입니다. 나머지는 손절선 너머
32,861건, 손절폭 부족 31,856건, 익절선 통과 1,360건으로 걸러집니다.

## 시간손절 결론은 그대로입니다

시간손절 비교는 **같은 스크립트 안에서 설정만 바꾼 상대 비교**이고,
이 인공물이 모든 설정에 동일하게 들어가 상쇄됩니다.
순서(120 < 180 < 300 < 600 < 900 < 무제한)와 슬롯 시뮬레이션의 총액 대소는
바뀌지 않습니다. **`--max-hold-sec 0` 권고는 유지됩니다.**

## 앞으로 이 프로젝트에서 백테스트를 짤 때

진입가를 확정한 뒤 **반드시** 라이브의 스킵 조건을 그대로 적용하십시오.
`risk` 를 터치가격이 아니라 **실제 진입가 기준**으로 다시 재는 것도 포함입니다.
이 가드가 없으면 결과가 좋은 쪽으로 크게 왜곡됩니다.

```python
if (ent <= stop) if isL else (ent >= stop):
    continue                      # 근접손절
if tp_bb > 0 and ((ent >= tp_bb) if isL else (ent <= tp_bb)):
    continue                      # 익절선통과
risk = abs(ent - stop) / ent      # 진입가 기준으로 다시 잰다
if risk * 100 < MIN_RISK_PCT:
    continue
```

## 왜 그런가 — 봉 마감 대기가 필터로 작동한다

BB 익절 비중이 결정적입니다.

| | BB 익절 비중 |
|---|---|
| 봉마감 진입 | **42.2%** |
| 터치 진입 | 14.2% |

EMA 를 찍고 그대로 흘러내리는 신호는 **봉이 닫힐 때쯤 이미 손절선을 넘어서
진입 자체가 걸러집니다.** 터치 순간 들어가면 그런 신호를 전부 받아버립니다.
60초 대기는 지연 비용이 아니라 **검증 시간**이었습니다.

## 옮기면 안 되는 결론

"진입 지연이 지배적 변수"는 **e1(급변동 추종)의 결론**입니다.
e2 는 눌림목 역추세라 성격이 반대입니다. e1 의 발견을 e2 에 그대로 옮기지 마십시오.
반대로 e2 의 발견도 e1 에 옮기면 안 됩니다.

**권고: e2 의 봉마감 진입 구조를 바꾸지 마십시오.**

# e2 운영 종료 (2026-08-20)

수수료 전 우위가 0 이라는 결과를 받고 사용자가 e2 중단을 결정했습니다.

## 종료 절차 (같은 작업을 할 때 이 순서를 지키십시오)

1. **봇 프로세스 먼저 종료** — 신규 진입을 막습니다. 포지션을 먼저 닫으면
   그 사이 봇이 다시 진입합니다.
2. 심볼별 **미체결 주문 전량 취소**
3. 전 포지션 **시장가 청산**
4. **잔여 확인** — 포지션 / 일반주문 / **알고주문** 세 가지를 모두 봅니다.
   알고주문(STOP_MARKET·TRAILING)은 `futures_get_open_orders()` 에 안 잡힙니다.

## 실제로 남아 있던 것

3번까지 마친 뒤 **알고주문 9건이 살아 있었습니다.**

```
AVAXUSDT 1 / HEMIUSDT 1 / TRUMPUSDT 1 / BOMEUSDT 1
REUSDT 3 (중복) / XLMUSDT 2 (중복)
```

전부 `reduceOnly=True` 라 새 포지션을 열지는 못합니다. 다만
**REUSDT 3건·XLMUSDT 2건의 중복이 고아 손절주문 버그(P0)의 흔적**입니다.
추가 진입 때 새 leg 수량으로 손절을 걸고 합산 수량으로 또 걸면서
앞의 것을 취소하지 않은 결과입니다. 수정 후에는 재발하지 않았습니다.

전량 취소했고 **포지션 0 / 일반주문 0 / 알고주문 0** 을 확인했습니다.

# 축 4 최종 판정 — 효과는 진짜지만 필요량의 9.6% 입니다

질문: **60초 시점 손실 건은, 그 이후에도 평균적으로 더 잃는가?**

# 진입가 버그 — 원장의 entry_price 는 체결가가 아닙니다

**수정은 코덱스 담당. 아래는 위치와 파급 범위 정리입니다.**

## 무엇이 잘못됐나

`pd["legs"]` 에 들어가는 값은 **EMA 지표값** 입니다.

```python
# scripts/scalp_bot_e2.py:1144-1149
targets = [ind["e5"], ind["e10"], ind["e15"]][: args.tranches]
k = len(pd["legs"])
if k < len(targets):
    tgt = targets[k]
    if (lo <= tgt) if L else (hi >= tgt):
        pd["legs"].append(tgt)          # <-- EMA 값. 체결가가 아니다
```

그리고 `Pos.entry` 는 이 값들의 평균입니다.

```python
# scripts/scalp_bot_e2.py:71-73
@property
def entry(self) -> float:
    return sum(self.legs) / len(self.legs) if self.legs else 0.0
```

반면 **실제 주문은 시장가**로 나갑니다(`ex.open_market_position`).
즉 원장의 `entry_price` 는 체결가가 아니라 **"EMA 선이 있던 자리"** 입니다.

## 왜 항상 유리한 쪽으로 기록되나

롱 눌림목에서 "캔들이 EMA5 를 찍었다"는 것은 **저가가 EMA5 까지 내려갔다**는 뜻입니다.
봉이 닫히고 다음 주기에 시장가로 들어갈 때 가격은 이미 그 위로 올라와 있습니다.

**기록 진입가(EMA5) < 실제 체결가** → 낮은 진입가로 계산한 ROE 가 실제보다 좋게 나옵니다.
숏은 방향만 반대로 같습니다. **계통오차이지 노이즈가 아닙니다.**

## 코덱스의 구분이 정확합니다

- ROE +, 실현손익 소폭 +, 수수료로 순손익 − → **정상**
- ROE +, **실현손익부터 −** → **진입가가 허수**

## 표시 문제만이 아닙니다 — 매매 동작에도 영향이 있습니다

이 값이 쓰이는 곳을 전부 확인하십시오.

1. **익절선 RR 1:2** — `entry * (1 + rr * risk)` 가 허수 진입가 기준으로 계산됩니다.
   실제 체결가 대비로는 손익비가 1:2 가 아닙니다.
2. **손절폭 risk** — `abs(entry - stop) / entry`. 진입 가드(`--min-risk-pct`)와
   `근접손절` 판정이 전부 이 값 위에 있습니다.
3. **청산 판정** — `mark >= pos.tp_rr` 등이 허수 기준선과 비교됩니다.
4. **명목 `nominal`** — `pos.entry * pos.qty`. 명목당 수익률 집계가 왜곡됩니다.
5. **`exit_price`** — 이쪽도 체결가가 아니라 **폴링 시점의 마크가격**입니다.
   같은 성격의 문제이니 함께 보십시오.

## 백테스트는 영향받지 않았습니다

이 세션의 백테스트 스크립트들은 진입가를 `ent = o1[s0]`(실제 다음 시가)로 잡고
수익률을 그것으로 계산합니다. `mean(legs)` 는 쓰지 않습니다.
**따라서 -0.1107%, 수수료 전 -0.0105% 등의 결론은 그대로 유효합니다.**

다만 초기 버전에는 `risk` 를 터치가격 기준으로 재는 문제가 있었고,
이는 진입 가드 패치에서 `risk = abs(ent - stop) / ent` 로 이미 고쳤습니다.
**라이브도 같은 방향으로 고쳐야 백테스트와 정합이 맞습니다.**

## 라이브 성적 재집계가 필요합니다

앞서 보고한 "라이브 48건 명목당 -0.041%" 는 `real_net / nominal` 인데,
`nominal` 이 허수 진입가에서 나옵니다. 부호는 바뀌지 않겠지만 크기는 다시 재야 합니다.
`real_net` 자체는 거래소 체결 기반이라 정확합니다.

**분자(real_net)는 맞고 분모(nominal)가 틀린 상태입니다.**
재집계할 때는 `real_realized_pnl / (실제체결가 × qty / leverage)` 로 하십시오.

## 수정 방향 (참고)

세 가지 선택지가 있습니다. 사용자에게 아직 확인받지 않았습니다.

1. **체결가 기반 전면 수정** — 진입 직후 `futures_account_trades` 로 실제 체결가를
   읽어 `legs` 에 넣습니다. 손절·익절선과 ROE 가 모두 실제 기준이 됩니다.
   API 호출이 진입당 1회 늘고, 체결 직후 조회라 지연이 생깁니다.
2. **기록만 수정** — 원장에 `entry_fill_price` / `roe_pct_real` 을 별도 필드로 남깁니다.
   분석은 정확해지지만 익절·손절선은 여전히 허수 기준으로 돕니다.
3. **마크가격으로 대체** — 주문 직전 `price` 변수를 `legs` 에 넣습니다.
   API 호출이 없고 EMA 값보다 훨씬 정확하지만, 체결 슬리피지는 반영되지 않습니다
   (e1 실측 진입 슬리피지 중앙값 +0.276%).

어느 쪽이든 `exit_price` 도 같이 처리해야 합니다.

브리핑·승률·복기가 전부 이 원장을 읽으므로 성적이 낙관 쪽으로 왜곡됐습니다.

## 원인 1 — 원장이 손실 거래를 통째로 빠뜨렸다 (기록 버그, 수정 완료)

`append_ledger` 는 **봇이 스스로 청산하는 경로(BB·RR 익절)에서만** 호출됩니다.
거래소 손절주문(STOP_MARKET)이 발동해 포지션이 닫히면 봇은 그 사실을 모르고
아무것도 남기지 않았습니다. **손절은 거래소가 대신 쳐주기 때문입니다.**

결과적으로 원장에는 **익절만 쌓이고 손절이 빠지는 구조적 낙관 편향**이 생겼습니다.

| | 값 |
|---|---|
| 거래소 실현손익 | -3.7701 |
| 거래소 수수료 | -1.6843 |
| 펀딩비 | +0.0057 |
| **실제 순손익** | **-5.4487** |
| 원장 기록 | +1.0113 |
| **누락** | **-6.46** |

거래소 실현손익 이벤트 **145건** vs 원장 **59건**. 절반 이상이 기록되지 않았습니다.
왕복거래로 재구성하면 **74건 중 15건(20%)이 원장에 없습니다.**

**수정**: 매 사이클 `reconcile_closed()` 가 거래소 실제 보유 목록과 봇의 `positions`
를 대조해 사라진 것을 찾고, 체결 이력으로 손익을 재구성해
`exit_reason="STOP_EXCHANGE"`, `external_close=True` 로 원장에 기록합니다.
남은 손절주문도 같이 정리합니다. 회귀 테스트 4건 추가.

**이것은 기록 버그이지 손실의 원인이 아닙니다.** 돈은 실제로 잃었고,
원장이 그걸 안 적었을 뿐입니다.

## 원인 2 — 손절이 제 역할을 못했다 (진입가 버그의 결과)

손실의 실체는 여기 있습니다.

```
-1% 초과 손실   10건 / 74건 (13.5%)   합계 -3.2776
전체 손익                              -3.5382
```

**10건이 전체 손실의 93% 를 만듭니다.**

손절선(EMA25)은 진입가에서 평균 **0.79%** 떨어져 있어야 합니다.
그런데 이 10건은 그 두 배 이상 밀린 뒤에 잘렸습니다.

### 인과 사슬

1. `pd["legs"]` 에 **EMA 지표값**이 들어감 -> `Pos.entry` 가 실제 체결가보다 유리
2. `risk = |entry - stop| / entry` 도 그 허수 진입가로 계산 -> `--min-risk-pct 0.35` 통과
3. **실제 체결가는 손절선에 훨씬 가깝다** (롱 눌림목은 EMA 위에서 체결되므로)
4. 일부는 체결 시점에 이미 손절선을 넘었는데 `근접손절` 가드도 허수 진입가로
   판정해서 못 걸렀다
5. 결과: 손절선이 잘못된 자리에 걸리거나, 진입 직후 즉시 발동

### 뒷받침하는 관측

| 보유시간 | 건수 | 가격 중앙 | 순손익합 | 손실비율 |
|---|---|---|---|---|
| **30초 이내** | 4 | -0.594% | -0.4994 | **100%** |
| 30초~2분 | 20 | +0.042% | -0.8142 | 55% |
| 2~5분 | 25 | -0.201% | -2.3195 | 60% |
| 5분 초과 | 25 | +0.085% | +0.0948 | 52% |

**30초 이내 청산 4건이 전부 손실입니다.** 정상이라면 30초 만에 0.79% 를 밀리는
일이 이렇게 몰릴 수 없습니다. 손절선이 체결가 바로 옆에 걸렸다는 신호입니다.

**수정**: 코덱스가 `entry_fill_after()` 로 실제 체결 평균가를 `legs` 에 넣도록 변경.
추가로 2·3차 진입에서도 `_since_id` 를 잡아 이번 차수 체결만 읽도록 보완했습니다
(0으로 두면 1차 체결이 섞여 '누적 평단'이 되고 1차가 중복 반영됩니다).

## 앞선 보고 정정

두 가지를 정정합니다.

1. **"라이브가 백테스트보다 낫다(-0.041% vs -0.111%)"는 틀렸습니다.**
   손실 거래가 원장에서 빠져 있어서 그렇게 보였습니다.
   실제 라이브(수정 전)는 명목당 **-0.276%** 로 백테스트보다 **나쁩니다.**
2. **"손실률이 기대치의 5배/40배"도 과장이었습니다.** 명목 기준을 잘못 잡았습니다.
   정확히는 **2.5배**(-0.276% vs -0.111%)이고, 표본 68건 기준 약 1.8시그마라
   통계적으로 확정할 수준은 아닙니다.
   다만 **-1% 초과 손실 10건이 손실의 93% 를 만든다**는 사실은
   표본과 무관하게 명확한 이상 신호입니다.

## 재가동 시 확인할 것

재가동의 목적은 수익이 아니라 **-1% 초과 손실이 실제로 사라졌는지 확인**입니다.

- 판정 기준: `-1% 초과 손실 비율`. 수정 전 15% 였다. 30건 이상 쌓고 볼 것
- 30건에서 0건이면 발생률이 10% 미만으로 떨어졌다고 볼 수 있다(단측 95%)
- 원장에 `external_close=True` 가 찍히는지 반드시 확인할 것.
  안 찍히면 `reconcile_closed` 가 안 도는 것이고, 다시 손실이 안 보이게 된다
- 브리핑 숫자와 거래소 `futures_income_history` 를 주기적으로 대조할 것.
  일치하지 않으면 집계를 믿지 말 것

**주의**: 이 수정들은 손실을 **정상 범위로 되돌리는** 것이지 전략을 흑자로
만드는 것이 아닙니다. 백테스트 기준 e2 는 여전히 명목당 -0.111% 이고,
수수료 전 우위가 0 이라는 결론은 그대로입니다.

# 원장 누락 — 1차 수정이 무력화돼 있었습니다 (재수정 완료)

**코덱스 확인 요청 사항입니다.**

## 무엇이 문제였나 — 처리기가 둘이었습니다

외부청산 처리기가 두 개 있었고, **원장을 쓰지 않는 쪽이 먼저 돌았습니다.**

| 위치 | 동작 | 주기 |
|---|---|---|
| 1078행 (코덱스) | `positions` 에서 **제거만** | 15초 |
| `reconcile_closed` (클로드) | 원장 기록 | 사이클 시작 |

15초 감시기가 먼저 목록에서 빼버리니, 기록 함수가 돌 때는 이미 사라져서 할 일이
없었습니다. 두 사람이 같은 문제를 각자 고치면서 서로를 무력화한 형태입니다.

증상: 로그에 `외부청산 감지 PUMPUSDT` 가 찍혔는데 원장 0건, 거래소 -0.1014.

## 재수정 내용

1. 기록 로직을 **`record_external_close(sym)` 하나로 통합**했습니다.
   체결 이력으로 손익을 재구성해 `exit_reason="STOP_EXCHANGE"`,
   `external_close=True` 로 원장에 남기고, 통계·쿨다운·상태파일까지 갱신합니다.
2. **15초 감시기가 반드시 이 함수를 거치도록** 했습니다. 바로 pop 하지 않습니다.
3. `reconcile_closed` 는 사이클 시작 **백스톱**으로 남겨 같은 함수를 호출합니다.
4. **텔레그램 전량청산 버튼(`flat_all`)도 같은 누락**이 있었습니다.
   봇이 직접 닫는데 원장을 쓰지 않고 지우기만 했습니다. 여기도 통합했습니다.

**원장을 거치지 않고 포지션을 지우는 경로는 dry-run 하나만 남았습니다.**
소스에서 `positions.pop(sm, None)` 전수 확인했습니다.

# 거래량 상위 심볼 자동 갱신 (2026-08-20)

사용자 지적: `SYMBOLS=AUTO` 인데도 e2 는 시작 시점의 거래량 상위 심볼만 잡고,
장중 거래량 순위 변화는 반영하지 않았습니다.

확인된 원인:

- `scripts/scalp_bot_e2.py` 기동 시 `get_active_usdt_perpetual_symbols(limit=args.symbols)` 를
  한 번만 호출했습니다.
- 이후 메인 루프는 같은 `symbols` 리스트만 계속 순회했습니다.
- WS 워커도 기동 당시 심볼셋으로 고정되어 있었습니다.

적용 패치:

1. `--symbol-refresh-sec` 옵션 추가. 기본값 `1800`초(30분), `0`이면 비활성화.
2. `SYMBOLS=AUTO` 일 때 주기마다 거래량 상위 심볼을 다시 조회합니다.
3. 변경이 없으면 아무것도 하지 않습니다.
4. 변경이 있으면:
   - 새 top 목록으로 `symbols` 갱신
   - 보유 중인 심볼은 top 에서 빠져도 목록에 유지
   - 제거된 비보유 심볼의 `pending` 만 정리
   - WS 워커를 새 심볼셋으로 재기동
   - WS 준비 전에는 기존 정책대로 보유 포지션 관리만 수행하고 신규/추가 진입은 대기

보유 심볼을 유지하는 이유:

- 거래량 순위에서 빠졌다는 이유로 보유 심볼을 스캔 대상에서 빼면,
  2차/3차 추가진입 상태나 보조 관리가 끊길 수 있습니다.
- 청산 자체는 `positions` 루프에서 계속 관리되지만, e2 의 1-2-3 원칙과 상태 일관성을 위해
  보유 심볼은 반드시 남겨야 합니다.

검증:

```text
.\.venv312\Scripts\python.exe -m py_compile scripts\scalp_bot_e2.py
OK

.\.venv312\Scripts\python.exe -m pytest tests\test_scalp_e2_bugs.py -q
37 passed
```

주의:

- 현재 실행 중인 프로세스에는 이 패치가 반영되지 않습니다. 재시작해야 적용됩니다.
- 심볼셋 변경 때 WS 워커가 재기동되므로, 갱신 직후 최대 100초 동안은 신규/추가 진입이 막히고
  보유 포지션 관리만 먼저 돕니다.

## 같이 발견한 보호주문 가격 포맷 버그

재시작 전 라이브 확인 중 `NEIROUSDT` 가 포지션은 열렸지만 STOP_MARKET 등록이 반복 실패했습니다.

에러:

```text
APIError(code=-1102): Mandatory parameter 'triggerprice' was not sent, was empty/null, or malformed.
```

원인 추정:

- `round_price("NEIROUSDT", 0.000083)` 는 float `8.3e-05` 를 반환할 수 있습니다.

# e2 maker/grid식 체결 1차 검증 (2026-08-21)

사용자 요청: e2 를 "수수료 덜 내는 그리드식 체결 구조"로 바꾸면 되는지 먼저 검증.

결론:

- **수수료 절감만으로는 e2 의 부호가 플러스로 바뀌지 않습니다.**
- 현행 e2 close-entry 리플레이 기준 거래당 평균은 `-0.082725%` 입니다.
- 왕복 taker 수수료 `0.1002%` 를 되돌린 수수료 전 우위는 `+0.017475%` 입니다.
- 따라서 신호 자체에는 아주 작은 gross 우위가 있지만, maker/maker 로 줄여도 아직
  `-0.022525%` 입니다.

수수료 구조별 1차 민감도:

| 체결 구조 | 왕복 수수료 | 거래당 | 26,116건 총합 |
|---|---:|---:|---:|
| taker 진입 + taker 청산(현행 가정) | 0.1002% | -0.082725% | -2160.4% |
| maker 진입 + taker 청산 | 0.0701% | -0.052625% | -1374.4% |
| maker 진입 + maker 청산 | 0.0400% | -0.022525% | -588.3% |

의미:

- maker 진입만으로는 거래당 약 `+0.0301%p` 개선됩니다.
- maker 진입 + maker 익절까지 모두 성공해도 약 `+0.0602%p` 개선에 그칩니다.
- 플러스가 되려면 maker/maker 이후에도 최소 `+0.022525%p` 의 추가 우위가 필요합니다.
  이 추가 우위는 지정가 미체결이 나쁜 거래를 걸러주는 선택효과나, 실제 체결가 개선에서
  나와야 합니다.

운영 판단:

- "그리드처럼 4/5/6차 물타기"는 아직 금지. 수수료 문제를 악화시키고 꼬리손실을 키웁니다.
- 가져올 수 있는 요소는 **maker 지정가 진입**, **실제 평균가 기준 TP/SL 재배치**,
  **익절 주문의 maker화** 뿐입니다.
- 다음 검증은 1분봉 OHLC 로 maker 지정가 체결률을 재는 것인데, 단순 전체 리플레이가
  로컬 PC에서 오래 걸렸습니다. `scripts/replay_e2_maker_grid_fee.py` 를 남겼고,
  기본 `--max-symbols 20` 으로 부분 샘플부터 돌리도록 해두었습니다.

주의:

- 이 검증은 수수료 민감도 1차입니다. 호가 큐, 부분체결, 미체결 후 슬롯 재배분은 반영하지
  못합니다.
- 바이낸스 그리드봇 수익과 e2 를 비교하려면 같은 기간, 같은 투입금, 같은 심볼, 실현손익 기준으로
  별도 대조해야 합니다.

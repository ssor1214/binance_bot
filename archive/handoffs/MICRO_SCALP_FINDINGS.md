## 부록 — 조기절단(120/180초) 재검증 (2026-08-17)

인수인계의 "120초/180초 조기절단을 지금 좋은 패턴에 얹으면 승률이 깨진다"는 결론이
**상태가 바뀐 뒤에도 유지되는지** 확인했다. 백스탑 1.5 배포(8/15 22:13)로 승률이
59%→63.7%로 오른 상태에서 재실행.

실행:
```bash
python scripts/replay_micro_scalp_klines.py --days 3 --targets 120 180
python scripts/replay_micro_scalp_klines.py --since "2026-08-15 22:13" --targets 120 180
```

| 구간 | actual(실제) | cut_120s | cut_180s | fast_reentry_15m |
|---|---|---|---|---|
| 최근 3일 (644건) | 59.0% / -28.64 | 50.6% / -15.94 | 50.6% / -20.73 | 58.3% / -28.10 |
| 백스탑1.5 이후 (344건) | **63.7% / -5.72** | 51.2% / -3.69 | 52.0% / -2.68 | **63.6% / -4.82** |

**결론 유지**: 조기절단은 여전히 승률을 11~12%p 깎는다. 손실 총액은 줄지만
"승률 유지 + 거래량 증가" 방향과는 반대다.

`fast_reentry_block_15m`도 인수인계 평가 그대로 — 승률 훼손 0.1%p로 사실상 없고 손익은
개선(-5.72→-4.82)되지만, 거래수가 344→286(**-17%**)이라 거래량 확대안이 아니라 안정화안이다.

**새 단서(미검증)**: 백스탑1.5 구간에서 조기절단이 **숏에서만 플러스**로 뒤집힌다
(cut_180s 숏 +0.69). 숏은 오래 들수록 나빠진다는 신호일 수 있으나 표본 97건으로 얇다.
숏 전용 보유시간 상한은 아직 검증되지 않은 별개 아이디어이므로, 표본이 쌓이면 따로 볼 것.

### 스크립트 수정 이력

- `THROTTLE_SEC=0.4` 추가 — **원래 REST 스로틀이 아예 없었다.** 이 저장소에서 실제 IP밴
  (약 10분 매매중단)을 냈던 패턴이라 페이지네이션 루프와 심볼 루프 양쪽에 넣었다.
- `--since "YYYY-MM-DD HH:MM"` 추가 — 설정 변경 전후를 분리해 비교하기 위함. `--days`보다 우선.
- 시간당 계산을 `--days`가 아니라 실제 경과시간 기준으로 수정(`--since` 사용 시 days가 무의미해짐).
